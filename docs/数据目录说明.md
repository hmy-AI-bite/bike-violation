# 数据目录说明

整理日期：2026-11-27。入口为项目根目录的 `data/`。

分类顺序为：来源 → 使用状态 → 数据阶段 → 批次/版本 → 训练/验证/测试划分。

```text
data/
├── network/                         网络来源数据
│   ├── used/                        已用于训练、验证、推理或开发
│   │   ├── raw/legacy_download/      下载原图，保留原始文件名与来源目录
│   │   ├── original_annotations/     下载附带的旧标签，质量有问题，单独保留
│   │   ├── pseudo_labels/           模型自动标注，不当成人工真值
│   │   └── annotated/bicycle_v2/     精修后的检测数据集
│   │       ├── images/{train,val,test}/
│   │       ├── labels/{train,val,test}/
│   │       └── data.yaml
│   ├── unused/{raw,annotated}/       预留给确认未使用的数据；目前为空
│   └── usage_unknown/               使用历史不清的数据；目前为空
├── campus/                          真实校园数据，包括从网盘接收的校园照片
│   ├── used/
│   │   ├── raw/batch_20261125/       66 张原图；images/ 内按点位、角度保留
│   │   ├── annotation_work/         未完成的标注、试标和误建的空标签

│   │       ├── images/{train,val,test}/
│   │       ├── labels/{train,val,test}/
│   │       ├── data.yaml
│   │       ├── polygons.json
│   │       └── scenes.json
│   ├── unused/{raw,annotated}/       预留给新采集、未用于开发的数据；目前为空
│   └── usage_unknown/               使用历史不清的数据；目前为空
└── manifests/
    ├── images.csv                   可用 Excel 打开的逐图清单
    ├── images.jsonl                 含哈希、标签状态、使用证据的逐图记录
```

## 当前实际数据量

| 数据 | 原图文件数 | 唯一图片数 | 当前用途 |
|---|---:|---:|---|
| 网络下载原图 | 553 | 153 | 原始来源归档；已参与重标、复核和数据构建 |
| 网络精修 bicycle_v2 | 153 | 153 | train 112、val 41、test 0；已用于微调及选权重 |
| 校园原图 batch_20261125 | 66 | 60 | 全部已推理，属于开发数据；其中 11 张独立图与旧校园数据相同 |
| 校园旧集 school_v1 | 17 | 11 | train 14、val 3、test 0；历史训练及验证 |

原始图与数据集中的图有内容重合，不能把各行相加当作新增样本数量。当前目录里没有已确认独立、未用于调参的最终测试集。

`used` 表示至少被用于过训练、验证、推理或开发查看，不等于所有图片都参与过训练。`images.jsonl` 中的 `known_training_roles` 通过图像哈希记录与既有训练/验证样本的完全重复关系；没有此证据不等于保证从未使用。校园原图有单独的开发推理使用证据。

网络下载原图中原有的 `images/train` 和 `images/val` 只是下载时的目录记录；对应的旧标签在 `original_annotations/legacy_download/labels/`。原 `data.yaml` 作为 `original_data.yaml` 保存，其中旧机器路径仅供追溯，不作为当前训练入口。

## 标注完成与未完成

- `annotated/` 保存既有可读取的检测框数据；其中旧校园标签还包含 `parking_area` 类。这里不承诺每条框都已重新复核，也不代表已有停车状态真值。
- `pseudo_labels/` 是模型提议，必须与人工精修数据区分。
- `annotation_work/batch_20261125/labels/` 保留收到校园图后产生的 66 个标签文件，目前只有 1 个非空、共 2 个框；没有配套人工停车状态记录。65 个空文件是未完成任务，不能当作已确认的负样本。
- `annotation_work/legacy_accidental/` 是旧校园图片目录内误建的空标签；不与正式 labels 合并。
- 网络精修数据原有 1 份 `.review.json` 仍保留，其停车状态均为“未标注”。

从标注工具打开 `data/campus/used/raw/batch_20261125/images` 或其中的点位子目录，框和 `.review.json` 会保存在对应的 `annotation_work/batch_20261125/labels` 中。原图目录不用于存新标签。同样规则适用于 `data/{network,campus}/{used,unused}/raw/<批次>/images`。

## 训练、验证和测试

- `train` 用于更新模型；`val` 用于选择模型和调参；`test` 用于最终评估。
- 现有 train/val 划分原样保留，以便复现实验，没有重新随机分配。
- 校园旧集有 2 组完全重复图片跨 train/val；已在 `summary.json` 中列明，因此旧验证指标不代表独立泛化性能。
- 两套正式数据集的 `images/test`、`labels/test` 已预留为空目录。`data.yaml` 没有启用空测试集，避免误以为已具备独立测试数据。
- 新测试集应来自新拍摄批次或新场地，并按场地、批次、近似重复组整体隔离。已经用于开发的数据不能靠换目录恢复成未使用数据。

## 下一批图片放哪里

1. 新的网络来源图放 `data/network/unused/raw/<批次>/images/`；真实校园实拍放 `data/campus/unused/raw/<批次>/images/`。传输途径是网盘，也仍归校园来源。
2. 不清楚是否用过的，先放对应来源的 `usage_unknown/`，写明来源、收集时间和已知使用历史。
3. 标注过程写入相邻分类下的 `annotation_work/<批次>/labels/`，保留原图不变。
4. 人工检查后，再组装有版本名的 `annotated/<版本>/images` 和 `labels`，并按场地/批次确定 train/val/test。
5. 记录每次使用：训练、验证选模、推理开发、最终测试。使用后及时更新目录与登记，不能长期停在 unused。

`tools/organize_data.py catalog` 当前登记本次迁移的两套数据集和两个原图批次，属于已知数据快照；新增批次需要扩展登记范围，不能把未登记理解为未使用。

## 常用入口

```powershell
# 查看实际使用的路径
python config.py show

# 精修网络检测数据
python config.py run labeler

# 标注本批校园原图；标签自动分离保存
python config.py run labeler data/campus/used/raw/batch_20261125/images

# 标定、推理与演示训练继续走已有入口
python config.py run zones
python config.py run detect
python config.py run train-demo

# 检查数据结构
python relabel/check_dataset.py --data data/network/used/annotated/bicycle_v2/data.yaml
python relabel/check_dataset.py --data data/campus/used/annotated/school_v1/data.yaml

# 核验这次迁移文件；已有文件被后续编辑时会报告差异
python tools/organize_data.py verify
```

内部调用 `config.data_path('dataset_v2/...')`、`config.data_path('dataset_school/...')` 的旧代码已映射到新目录，保存的实验输入路径通过 `resolve_project_path` 解析。手动执行旧文档里的相对路径命令时，应改用本页的新路径。`.env` 中显式覆盖的数据路径也需相应更新；本机现有 `.env` 没有旧数据路径覆盖。

## 核验与回退

迁移记录覆盖 3,255 个文件、1,510,137,712 字节；迁移前后逐文件核对 SHA-256。没有删除重复原图、旧标签或备份，旧目录只移除已经为空的容器。

`python tools/organize_data.py rollback` 只回退清单内的文件，不覆盖现存同名文件，也不撤销源码修改。若任何迁移文件已被后续修改，它会停止，避免以回退覆盖新工作。回退后配置可回落到仍存在的旧目录；回退前应关闭标注、训练等写文件的程序。额外生成的清单、空测试目录和新查看器不属于迁移原文件，会保留。

迁移工具已用临时样本验证完整往返、源文件变化、目标冲突、路径越界、部分迁移续跑及重复执行。当前真实数据只执行正向迁移及校验。
